# Perception Web Motion

把内容组织成“提出能力 → 展示过程 → 解释机制 → 给出证据”的科技展示页。
视觉参考来自 Tencent WeVisOne-VL 项目页；复用其视觉语法和实现机制，不照搬论文、品牌、作者或模型结果。

## 先确定承载环境

- **完整网页**：在现有项目的技术栈中实现。无现有框架时，原生 HTML/CSS/Canvas 2D/JavaScript 就足够。
- **已有页面改造**：先保留用户的信息架构、数据来源、路由和组件约定，按需加入动效。
- **GitHub 个人页 / README**：先读 [GitHub 适配](references/github-readme.md)。主要动效可自动播放，完整网页交互不能嵌入 README。
- **只分析参考网页**：先读 [原站源码拆解](references/wevisone-source-audit.md)，给出“观察到的效果 → 对应源码 → 实现机制”，不凭外观猜测库。

普通表单、后台业务界面不必套用整套沉浸式展示布局。用户已有配色、品牌和内容约束时，以用户选择为准。

## 核心视觉语法

用几层轻量机制组成整体，而不是把所有元素做成动画：

1. **深色空间**：近黑背景、低透明面板、细边框；薄荷绿 / 青 / 紫作为强调色。正文保留足够对比，装饰退到文字后面。
2. **分工明确的字体**：展示标题用几何无衬线，正文用易读无衬线，指令、坐标、状态与代码用等宽。缺少字体文件时设置可靠的系统回退。
3. **首屏的“机器在观察”隐喻**：CSS 径向渐变柔光 + Canvas 点阵 / 框 / 点 / 标签。避免把随机粒子当成无关装饰；换成与用户内容有关的信号。
4. **有节制的连续动效**：标题渐变缓慢移动，背景轻漂移，光标闪烁。按钮反馈短，段落进入适中，背景变化慢。
5. **过程可见的演示**：输入、输出和图形处在同一个演示容器；文本状态变化与图形变化共享进度，而不是各自播放。

“绿色发光卡片”不是充分条件。至少让一个视觉行为与页面主题有明确联系。

## 从参考到实现

需要技术细节时读 [实现配方](references/implementation-recipes.md)。
以原站为依据时读 [源码拆解](references/wevisone-source-audit.md)，其中区分了真实运行模块、未挂载模块和建议改进。

### 组织内容

先写清用户的身份 / 产品能力、首要行动和能够证明它的内容。通常可用：

首屏 → 一段简介 → 核心演示 → 方法 / 特点 → 有来源的结果或项目 → 资源。

没有真实实验数据时，改用项目、流程或实物演示，不生成假 benchmark、准确率、延迟、用户数或“实时推理”状态。演示若使用预设数据，靠近演示标明“示意 / replay”；用户提供真实录制结果时保留其来源。

### 建立样式与动效层

- 用 CSS 变量定义背景、文字、强调色、边框、间距和字体，避免把颜色散落在组件里。
- 用 `background-clip: text` 做渐变文字；用独立背景层做柔光，不对正文加模糊。
- Canvas 只承担密集、短生命周期的装饰几何；正文、按钮、标签和可交互内容使用语义 DOM 或 SVG。
- 用 `IntersectionObserver` 启动段落显现和一次性数字动画；CSS 默认让内容可见，增强初始化成功后再启用隐藏态。
- 卡片聚光用局部指针坐标写入 CSS 变量；轻倾斜只在精细指针和允许动态时启用。与滚动显现分属不同包装层，避免争抢 `transform`。

### 让文字驱动图形

把演示视为小型状态机，至少包含：

`ready → preparing → replaying → complete`，另有 `error / cancelled`。

1. 数据声明任务、输入素材、提示词、结构化输出及可选蒙版；展示层不散落业务数据。
2. 回放按 token 或事件推进。原站用语义标签、归一化坐标和 `<OBJ>` 触发视觉；别的主题可换成检索片段、图节点、地图路径、时间线等。
3. 文本高亮与图形更新来自同一组事件。在需要的坐标数量凑齐时出现框 / 点；只有对应事件到达才显露预先准备的蒙版。
4. 重播、切换和卸载都会取消旧任务。每次异步等待后、提交图形或状态前检查运行身份。
5. 自动播放在演示进入视口后启动；用户手动操作后停止自动切换。离开视口或标签页隐藏时停止不必要的工作。

原站的蒙版演示是已经准备好的图像显露，不是浏览器在运行分割模型。不要把回放包装成真实推理。

### 性能、可访问性与布局

- Canvas 的 CSS 尺寸与像素缓冲区分开处理；像素比设置上限，resize 后重设坐标变换。手机降低点密度和对象数量。
- 动画循环只有一个明确的拥有者；取消 RAF、清理监听和 observer，避免重挂载后加倍运行。
- `prefers-reduced-motion` 与页面上的动效开关覆盖 CSS、RAF、打字和自动轮播。减少动态时直接呈现可读的完成状态。
- 状态摘要可用 `role="status"`；不要让屏幕阅读器逐字朗读循环终端。演示 tabs 支持键盘、选中状态和 panel 关联。
- 图像与覆盖层共享坐标空间。缩放、裁切、留白或换图后重新核对，不能只看桌面截图。
- 手机将双栏演示堆叠；允许 tab 换行 / 横向滚动，终端长 token 换行或在容器内滚动，防止整页横向溢出。

## 可运行起点

[assets/starter/](assets/starter/) 是独立编写的轻量示例，不包含 Tencent 的图片、文案、模型输出或源码。

复制整个目录到目标项目即可预览：

```sh
python3 -m http.server 8080 --directory /absolute/path/to/starter
```

- `content.js`：修改品牌、标题和演示数据。
- `styles.css`：修改视觉变量、布局和 CSS 动效。
- `app.js`：Canvas、指针反馈、生命周期和同步回放。
- `index.html`：语义结构与独立绘制的示意场景。

已有 React/Vue 等项目时抽取机制并接入其生命周期，不为套模板重建项目。参考中的附加模块（结果条形图、图像对比、lightbox）仅在内容需要时实现。

## 验证与交付

至少实际查看首屏、滚动后内容和完整演示一次。验证：

- 框 / 点 / 蒙版与输入对齐；快速切换后旧输出不混入新任务。
- 手动切换停止自动抢页，重播可恢复同一任务，切后台后不继续消耗动画工作。
- 手机没有整页横向溢出，关键文本可读；动效关闭和系统减少动态时页面仍完整。
- 页面无运行错误，网络失败时保留说明和可恢复入口。

交付可编辑文件、实际预览截图、运行方式及已验证范围。发布、上传、修改仓库沿用当前用户的授权；skill 本身不授予额外的发布权限。
