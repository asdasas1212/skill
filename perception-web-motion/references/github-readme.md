# GitHub README 的受限适配

仅在用户的目标是 GitHub 个人页或 README 时读取。
不要把这一受限环境的做法推广为普通网页的默认实现。

## 先说清能力边界

GitHub 会清理 Markdown 里的脚本、iframe 和任意页面样式。
因此不能把完整 HTML 网页、Canvas 程序、鼠标跟随和可点击 tabs 原样嵌入个人页。
参考 GitHub 的渲染处理说明：
https://github.com/github/markup#github-markup

用户若要求“打开个人页就看到，不用点进去”，直接把主要视觉过程放进首屏的自托管动画 SVG，
或按需使用 GIF/APNG。完整交互网页仅作为可选链接，不能仍然只给一个入口就声称问题解决。

## 自动播放 SVG

一个自包含 SVG 可以同时呈现标题、柔光、点阵、终端、场景和阶段演示：

- 用 CSS keyframes 控制每个阶段的透明度；进度条和阶段标签共用同一循环时长。
- 预先绘制 SVG 几何，通过 stroke-dashoffset、transform、opacity 呈现路径和对象移动。
- 文字使用 clipPath + steps 模拟打字；字体有系统回退，避免外部字体依赖。
- 同步 token 和几何的结果预先编排；这是固定回放，不能声称运行了真实交互逻辑。
- 减少动态时关闭循环，显示可理解的静态完成态；内容需有 title、desc 和 README alt。
- 不使用 script、foreignObject、外部 fetch、事件处理器或需要跨域资源的构图。

```html
<img src="./assets/project-showcase.svg" width="100%"
     alt="项目能力的自动循环演示；预设场景示意。">
```

## 首屏与清晰度

按 GitHub 中实际显示的 README 列宽排版，而非按 SVG 的导出像素数判断。
把主视觉与关键过程压缩进一块区域，避开过多文字，把详细介绍留在下面。
对于手机，优先简化终端内容或使用 `<picture>` 的窄屏版本，不把完整桌面界面等比例缩成难读小字。

在实际 GitHub 个人页验证：

1. 图片已加载，尺寸正确，不是仅在本地 SVG 查看器里能播放。
2. 至少观察两种阶段，确认平台代理 / 缓存没有破坏动画。
3. 无需点击即可观看，且“更多互动”链接不是观看主要动效的前提。
4. 保存能体现 GitHub 周边界面的截图，说明这是一段自动回放，不能操作网页按钮。

如果 SVG 动画无法在目标客户端播放，才改用有尺寸与帧率预算的 GIF/APNG。
不要为了上传图片而自动创建凭据、修改浏览器安全设置或更改仓库可见性。
